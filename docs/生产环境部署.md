# 生产环境部署

> 定位：short-lab 是**单机桌面应用**，没有中心服务端。“生产部署”= 打包分发版的构建 → GitHub Release 发布 → 用户机器安装运行。
> 服务永远只监听本机（默认 `127.0.0.1:46408`），不要改成 `0.0.0.0` 对外提供服务。

## 1. 打包（构建分发版）

官方构建在 CI（`windows-latest`）完成，命令与本地一致：

```bash
cd desktop/backend
uv sync
uv run --with pyinstaller pyinstaller short-lab.spec --noconfirm
```

产物：`dist/short-lab/`（onedir 目录，不是单文件——单文件易触发杀毒误报且每次启动要解压）。
`dist/short-lab/short-lab.exe` 即主程序，双击/命令行运行，服务 `127.0.0.1:46408` 并自动打开 UI。

spec 已包含的关键内容：DuckDB 原生库、`shortlab/default.yaml` 默认配置、预构建 React（`desktop/ui/dist`，改完前端必须先 `node build.mjs` 再打包，否则发的是旧界面）。

**可写数据**：打包版绝不写安装目录。Short-Lab 状态（`shortlab.duckdb`）在各系统用户数据目录：

| 系统 | 路径 |
|---|---|
| Windows | `%LOCALAPPDATA%/short-lab/shortlab.duckdb` |
| macOS | `~/Library/Application Support/short-lab/shortlab.duckdb` |
| Linux | `~/.local/share/short-lab/shortlab.duckdb` |

可用 `SHORTLAB_DATA_DIR` 显式覆盖。包体解压后约 150–250MB（pandas/numpy 主导，正常）。

## 2. 发布（GitHub Release）

Tag 路由（`.github/workflows/release.yml`，有静态测试锁定）：

| Tag | 触发 |
|---|---|
| `v*`（如 `v0.4.0`） | 仅 Android（APK + AAB） |
| `short-lab-v*`（如 `short-lab-v1`） | 仅桌面：打包 → 建 GitHub Release → 挂 `short-lab-windows-x64.zip` |
| 手动触发（Actions → Release → Run workflow，勾 `package_desktop`） | 仅桌面：只上传 artifact，不建 Release |

发布说明须标注：Desktop-only、研究工具（非自动交易）、provider 依赖。Android 版本号不随 Desktop tag 增长。

> 已知机器限制：超 1MB 的 `git push` 在作者机器上失败，打 tag/发版走 GitHub REST API 或 `gh release create`，详见 `docs/packaging.md` 末节。

## 3. 用户机器安装与运行

1. 从对应 `short-lab-v*` Release 下载 `short-lab-windows-x64.zip`，解压到任意目录（**整个 `dist/` 树一起解压**，保持 `dist/ui` 镜像目录与主程序的相对位置）。
2. 运行 `dist/short-lab/short-lab.exe`，浏览器自动打开 `http://127.0.0.1:46408/`。
3. 首次打开 Short Lab 页为空是正常的（无评分轮次）：点“刷新”触发后台回填（全市场约 30–35 分钟），之后候选列表出现。

冒烟清单（发版前/安装后二选一执行）：只读解压目录启动**两次**，确认第二次仍读写同一用户数据目录的 `shortlab.duckdb`；旧 `/api/scan` 正常；Short Lab 页可开；重启后缓存仍在。

## 4. 配置与升级

- provider key（CoinGecko 等）只通过环境变量注入，不写进包里。
- 用 `SHORTLAB_CONFIG_PATH` 指向自定义评分 YAML；升级前先备份用户数据目录。
- 同一 Python 环境内升级：先卸载旧 `diveintocrypto-desktop`，再装 `short-lab-desktop`，绝不同时安装。
- 回滚：Release 页保留历史 zip，解压旧版即回滚；用户数据目录的 duckdb 向前兼容保留（破坏性迁移必须走显式工具+备份，应用不会自动删库）。

## 5. 不在范围

- V1 无交易执行、无账号体系、无需数据库/Redis 等外部服务。
- Android 用 `v*` tag 独立发布，本流程不动它。
